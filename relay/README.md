# fly-web LAN-релей

Небольшой Node.js-сервер для игры в **локальной сети без интернета**: отдаёт
статику игры и раздаёт состояние игроков по WebSocket. Топология «звезда» —
у каждого клиента одно соединение, число соединений O(N), стабильно для
десятков участников. Без auth-web и TURN.

## Запуск (машина-хост в локальной сети)

Требуется **Node.js 18+**.

```bash
cd fly-web/relay
npm install          # один раз (нужен пакет ws)
npm start            # или: PORT=8080 node server.js
```

Затем узнайте IP хоста в локальной сети (`ipconfig` / `ip a`) и раздайте
игрокам адрес вида:

```
http://<IP-хоста>:8080/?lan
```

Параметр `?lan` (или сам протокол `http:`) включает режим релея. Игрок вводит
имя, видит список открытых игр, создаёт свою или подключается к нужной.

Проверка: `http://<IP-хоста>:8080/healthz` → `ok`.

## Соревнование класса

Турнир для класса запускается с сайта `https://fly.nayanovaacademy.ru`:
«Сетевая игра» → «🏆 Соревнование класса». Учитель входит через портал
(централизованный логин), выбирает класс из auth-web и отмечает присутствующих.
Сайт открывает доску турнира на релее; ученики логин не вводят.

Порядок:

1. На машине-релее:
   ```powershell
   cd fly-web/relay
   npm install
   $env:ADMIN_KEY="<ключ>"
   npm start
   ```
   Ключ и готовые ссылки для ПК показывает мастер создания соревнования.
2. На каждом компьютере R114 откройте `http://<IP-хоста>:8080/station.html`
   и один раз выберите метку `R114-01…R114-19` (сохраняется в браузере), либо
   сразу откройте ссылку вида `http://<IP>:8080/?lan&station=R114-01`.
3. На доске администратора нажмите «Создать и открыть доску» (на сайте) —
   релей построит сетку заездов и покажет, кто за каким ПК должен сидеть.
4. Старт каждого заезда, завершение и переход к следующему — только с доски
   администратора. Во время заезда работает режим наблюдателя: общий 3D-обзор,
   таблица гонщиков, карта и текущее турнирное положение.

Сетка: отборочные заезды до 6 человек, затем финал; каждый участник получает
итоговое место. В мастере на сайте учитель выбирает **количество участников**
и **задействованные компьютеры** (`R114-01…R114-19`). Размер заезда —
`min(6, компьютеров, участников)`, поэтому при 3 ПК заезды идут по 3 человека.
Сервер сам назначает учеников на **подключённые выбранные** компьютеры.
Если выбранный ПК не подключён, старт блокируется и на доске перечислены
недостающие места; незадействованные ПК показывают ученику, что они не в игре.

Доска переживает перезагрузку вкладки: откройте тот же адрес
`http://<IP>:8080/?lan&admin=<ключ>&compadmin=1` — новый администратор забирает
управление, сетка и результаты сохраняются. Закрытие вкладки не удаляет турнир:
завершайте его кнопкой «Закрыть соревнование».

Состояние турнира сохраняется в `relay/data/competition.json` (каталог в
`.gitignore`): сетка, результаты, назначения и текущий этап переживают
перезапуск релея. Если релей выключили прямо во время заезда, после старта этот
заезд возвращается в подготовку и его нужно запустить заново — результаты
незавершённого заезда не засчитываются. Кнопка «Закрыть соревнование» удаляет
файл состояния.

## Структура

```
relay/
  server.js       # HTTP-статика + WebSocket /ws, турнир класса
  data/           # competition.json — сохранённое состояние (в .gitignore)
  package.json    # зависимость ws
  README.md
../public/        # та же статика, что деплоится на прод (используется релеем)
```

Релей отдаёт `../public`, поэтому правки в `public/` подхватываются сразу.

## Протокол (JSON)

Клиент → релей:
- `hello{name,admin?,station?,compadmin?}` — имя, ключ администратора,
  метка компьютера `R114-01…R114-19` и признак страницы доски турнира;
- `lobby` — запросить список игр;
- `create{title,max?,pair?,director?}` — создать игру (хост). `pair:true` — парная
  гонка 1×1: только для администратора, 3 слота (наблюдатель + 2 гонщика).
  `director:true` — гонка с наблюдателем: 7 слотов (админ + до 6 гонщиков);
- `join{roomId}` — подключиться;
- `quick` — быстрая игра (в первую неполную или новая; парные комнаты пропускаются);
- `control{map,mode,started,max,title,race?}` — управление (только хост);
  `race` — ID трассы (`utt1/utt2/utt5/utt4/forest`);
- `comp_create{title,classId,className,track,adminName,students[],stations[]}` —
  создать соревнование класса (только администратор); `students` — участники,
  `stations` — выбранные компьютеры (если не переданы — все 6). Размер заезда
  сервер считает как min(6, число компьютеров, число участников);
- `comp_sync` — запросить текущее состояние турнира;
- `comp_start` / `comp_finish` / `comp_next` — старт заезда, досрочное завершение,
  подготовка следующего (только администратор);
- `comp_set_track{track}` — сменить трассу до первого заезда;
- `comp_close` — закрыть соревнование (только администратор);
- `st{p,q}` — состояние борта (позиция + кватернион);
- `leave`.

Релей → клиент:
- `lobby{rooms,maps,races,maxOptions,maxHard,self}`;
- `welcome{self,room,participants,maps,races,maxOptions,maxHard,isAdmin}`;
- `room{room,participants}` — при любом изменении состава/параметров;
- `comp{comp,self}` — состояние турнира: сетка, заезды, назначения на ПК,
  standings, `self.active`/`self.sid`; `comp:null` — турнира нет;
- `st{id,p,q}` — состояние других игроков;
- `error{message,code?}` — ошибка; `code:'room_closed'` — админ закрыл парную гонку,
  `comp_closed` / `comp_full` / `comp_no_stations` — турнир;
- `ready/go/reset/race` — сетевой забег (пересылаются остальным участникам).

В парной комнате у хоста-администратора роль `spectator`, у остальных —
`racer`. Админ не летит, а получает состояние обоих гонщиков и показывает
сплит-скрин FPV и статистику. Если админ выходит, комната закрывается.

## Несколько релеев и комнат

- На одном релее можно создать сколько угодно комнат — они видны в списке
  «Открытые игры», и каждый подключается к нужной.
- Клиент может подключиться к **другому релею по IP**: в окне «Сетевая игра»
  поле **«Релей»** (`host[:port]`, порт по умолчанию `8080`) и кнопка
  «Подключиться». Адрес запоминается в браузере. Так можно держать несколько
  релеев (на разных машинах) и переключаться между ними.
- Название новой игры задаётся в поле «Название новой игры».

## Ограничения и заметки

- Размер комнаты 2/4/6/8 (потолок 8). **Больше 4 — только администратор**:
  запустите релей с `ADMIN_KEY=<секрет>`, а админ открывает игру по адресу
  `http://<IP>:8080/?lan&admin=<секрет>`. Без `ADMIN_KEY` все считаются
  обычными игроками (макс. 4). Слотов ровно столько, сколько мест.
- **Парная гонка 1×1**: админ нажимает «🏁 Парная гонка 1×1» и выбирает трассу.
  Комната занимает 3 слота (админ-наблюдатель + 2 гонщика), подключаются по
  списку открытых игр. Гонщики могут входить и с сайта, и с релея — это разные
  комнаты в разных транспортах.
- **Гонка с наблюдателем (до 6)**: админ нажимает «🎬 Гонка с наблюдателем»;
  комната занимает 7 слотов (админ + до 6 гонщиков). На экране админа — общий
  3D-обзор, таблица, карта и переключение на FPV выбранного гонщика.
- **Соревнование класса**: только администратор (`ADMIN_KEY`). Комната скрыта из
  общего лобби, ученики входят по метке ПК (`?station=`), без логина. Сервер
  строит сетку, ограничивает заезд 6 гонщиками и сам назначает учеников на
  подключённые ПК. Сайт передаёт состав класса в hash ссылки; сам список в
  открытом виде на сервер релея не пишется.
- **Вход учеников с сайта**: кнопка «🏁 Парная гонка» открывает
  `http://10.12.6.23:8080/?lan&pair=1`, кнопка «🎬 Гонка с наблюдателем» —
  `http://10.12.6.23:8080/?lan&director=1`; клиент сам открывает сетевое окно
  и автоматически входит в первую открытую комнату нужного типа.
- На сайте адрес релея по умолчанию — `10.12.6.23:8080`; кнопка «Открыть релей»
  ведёт на `http://10.12.6.23:8080/?lan`.
- Порядок запуска: хост первым создаёт игру, остальные подключаются по адресу
  `http://<IP>:8080/?lan`.
- Порт меняется переменной `PORT` (по умолчанию 8080); на хосте должен быть
  открыт в firewall.
- Трафик локальный: интернет, auth-web и TURN не используются.
- Для автономной работы без интернета страница не требует входа; имя — локальное
  (хранится в localStorage браузера).
