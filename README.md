# fly-web — симулятор полёта БПЛА

Самодостаточная статическая страница-симулятор полёта квадрокоптера/шестироторника
на **three.js** (vanilla JS, без сборки и серверной части).

**Демо:** https://fly.nayanovaacademy.ru

## Возможности

- **Полётная модель**: физически-аркадная, с реалистичным acro-режимом.
- **Выбор БПЛА**: 4 модели с мгновенной пересборкой меша (Пионер Мини 2, Базовый,
  FPV Racing, Гекса-разведчик) + настройка моторов/винтов/аккумулятора.
- **Режимы полёта**: Angle (автостабилизация) и Acro (угловые скорости,
  кватернионная ориентация, петли/роллы).
- **15 обучающих упражнений**: взлёт/посадка, рыскание, висение, слалом,
  развороты, точная посадка, полоса препятствий, восьмёрка, коридор,
  гонка на время, диагонали, узкие ворота, отказ мотора, свободный полёт.
- **Свободный полёт** с процедурными картами: Луг / Город / Каньон.
- **Камеры**: Погоня, Сверху, Фиксированная, **FPV** (вид от первого лица,
  авиагоризонт, компас-лента, SPD/ALT/вариометр).
- **USB-пульт** (Gamepad API, BetaFPV и любой HID): калибровка осей и кнопок,
  конфиг в localStorage.
- **Клавиатура и мышь/тач**: WASD + стрелки, виртуальные стики (мультитач).
- **Сетевая игра**: несколько комнат одновременно, mesh «каждый с каждым».
  Размер комнаты выбирает хост (2/4/6/8, потолок 8 — удобно для игры в локальной
  сети). Список открытых игр и подключение к нужной; первый участник — хост,
  выбирает карту, режим, размер и жмёт «Начать игру». Сигналинг — HTTP-поллинг
  PHP-бэкенда (`/api/signal/*`), авторизация по куке `auth_session`; после
  установки DataChannel трафик P2P. Над бортами показываются имена.
- **Сворачиваемые окна и панели** интерфейса, адаптив под телефоны,
  максимально полноэкранный режим на мобильных.
- **Вход через портал auth-web** (SSO, кука `auth_session`): имя пользователя и
  кнопка «Выйти» в панели «УПРАВЛЕНИЕ» и на стартовом экране. Анонимный вход
  разрешён — симулятор полностью доступен и без авторизации.

## Структура

```
public/                     # webroot
  index.html                # разметка UI
  style.css                 # все стили
  app.js                    # вся логика
  three.module.min.js       # локальная копия three.js r160
  api/signal/               # тонкие PHP-фронт-контроллеры сигналинга

  auth-client/AuthClient.php
  lib/Db.php, http.php
  api/find.php, exchange.php, leave.php
fly.nayanovaacademy.ru      # nginx-конфиг сайта (location PHP для /api/)
deploy.ps1                  # деплой на сервер (public/ -> webroot, server/ -> app/)
.env.example                # шаблон переменных окружения (скопировать в .env)
AGENTS.md                   # заметки по проекту и критическим правилам
```

## Сигналинг сетевой игры (бэкенд)

Сетевой режим больше не требует ручного обмена кодами: `app.js` сам обращается
к PHP-бэкенду за комнатой и SDP. PHP — единственная серверная часть (без Node и
без WebSocket), состояние — в SQLite вне webroot
(`/var/www/fly.nayanovaacademy.ru/data/signaling.db`).

Можно вести **несколько игр одновременно**: в окне «Сетевая игра» показывается
список открытых комнат, и участник подключается к нужной (или жмёт «Быстрая игра»).
Первый участник комнаты — **хост**: он выбирает карту (Луг/Город/Каньон) и режим
полёта (Angle/Acro) и нажимает **«Начать игру»**; выбор и старт транслируются
остальным, те автоматически переходят на карту хоста.

- **Эндпоинты** (только POST, JSON, авторизация по `auth_session` через
  канонический `AuthClient`):
  - `/api/signal/rooms.php` — список открытых игр;
  - `/api/signal/create.php` — создать игру (я — хост);
  - `/api/signal/join.php` — подключиться к конкретной игре (`room_id`);
  - `/api/signal/find.php` — «быстрая игра» (самая старая незаполненная или новая);
  - `/api/signal/exchange.php` — обмен SDP + heartbeat + состав + управление хоста
    (`control:{map?,mode?,started?,title?}`, применяется только от хоста);
  - `/api/signal/ice.php` — ICE-серверы: STUN + TURN с временными креденшелами;
  - `/api/signal/leave.php` — выход (хост переназначается, пустая комната удаляется).
- **NAT-обход**: кроме публичных STUN работает собственный **TURN (coturn)** на
  `fly.nayanovaacademy.ru:3478` (UDP/TCP). Креденшелы временные (REST-авторизация
  coturn, `use-auth-secret`); секрет лежит вне webroot в `data/turn_secret` и
  клиенту не отдаётся. Без TURN при общем/симметричном NAT игроки не соединяются.
- **Старт**: когда хост нажимает «Начать игру», окно закрывается само и все
  переходят в игру (без нажатия «Готово»); событие `started` приходит через
  `exchange`.
- **Инициатор пары** — участник с меньшим `user_id`, поэтому в каждой паре ровно
  один offer; дальше WebRTC DataChannel `fly` работает P2P.
- **Точки спавна**: каждому игроку сервер выдаёт слот 0–3 (наименьший свободный),
  клиент ставит дрон в свою точку `NET_SPAWNS[slot]` — при старте участники
  появляются рядом, а не в одной точке. Слот освобождается при выходе.
- **Лимиты**: размер комнаты задаёт хост (`rooms.max`, значения 2/4/6/8; жёсткий
  потолок `FLY_MAX_PLAYERS=8`), SDP ≤ 32 КБ, rate-limit поллинга на игрока.
  **Больше 4 участников (`6`/`8`) — только администратор** (`is_admin` из
  auth-web): сервер клампит до `FLY_PUBLIC_MAX=4`, а `maxOptions` для не-админа
  возвращается `[2,4]`. Mesh масштабируется как O(N²): при 8 участниках у каждого
  7 соединений; в локальной сети это нормально, через интернет помогает TURN.
- **Разовая настройка на сервере (root):** каталоги `app/` и `data/` рядом с
  `public/`, владелец — `deploy:www-data` (у пользователя `deploy` нет прав
  создавать каталоги в `/var/www`), `data/` доступен на запись PHP-FPM.
  Для TURN: `apt-get install coturn`, `/etc/turnserver.conf` с `use-auth-secret`,
  `static-auth-secret` (тот же — в `data/turn_secret`, `www-data` 640),
  `external-ip`, `min-port=49160..max-port=49200`, `denied-peer-ip` для приватных
  сетей; сервис coturn включён. Порты 3478/udp+tcp и 49160-49200/udp — открыты.
- Локально бэкенд ищется в `server/` (см. `public/api/signal/_bootstrap.php`);
  путь к данным можно переопределить переменной `FLY_DATA_DIR`.

## Локальная сеть (LAN-релей)

Для игры в локальной сети без интернета (и для большого числа участников) есть
отдельный сервер `relay/` — см. `relay/README.md`. Он отдаёт статику игры и
раздаёт состояние по WebSocket: топология «звезда», у каждого клиента одно
соединение (O(N)), без auth-web и TURN. Запуск на машине-хосте:

```bash
cd relay && npm install && npm start        # http://<IP>:8080/?lan
```

Режим релея включается на `http:` или параметром `?lan`/`?relay=host:port`;
на https-проде клиент автоматически использует прежний WebRTC-mesh. В окне
«Сетевая игра» можно сменить **релей по IP** (`host[:port]`) и задать **название
игры**; на одном релее — много комнат одновременно.

С **https-сайта** (`fly.nayanovaacademy.ru`) в окне «Сетевая игра» есть поле
**«Релей»** с кнопкой **«Открыть релей»**: она открывает страницу локального
релея (`http://<ip>:<port>/?lan`) в новой вкладке. Прямое `ws://` к LAN-IP с
https-страницы браузер запрещает (mixed content), поэтому переход делается
именно новой вкладкой; там игра идёт целиком по локальному релею.

## Локальный запуск

Сборки нет, но `app.js` — ES-модуль, поэтому открывать нужно через HTTP, а не `file://`:

```powershell
# любой статический сервер из каталога public
npx serve public
# или
python -m http.server 8080 --directory public
```

## Деплой

```powershell
.\deploy.ps1 -DryRun   # показать команды
.\deploy.ps1           # выложить public/ на сервер и обновить nginx
```

Настройки подключения — в `.env` (см. `.env.example`). Файл `.env` с секретами
в репозиторий не коммитится.

## Управление

- **Mode 2**: левый стик — газ (↑/↓) и рыскание (←/→); правый — тангаж (↑/↓) и крен (←/→).
- Клавиши: `W/A/S/D` — газ и рыскание, стрелки — тангаж и крен, `C` — камера,
  `F` — режим Angle/Acro, `R` — заново, `N` — следующий уровень, `M` — модель
  и оборудование, `1…9`/`0` — выбор уровня, `Esc` — меню.
- Мышь/тач: виртуальные стики; на телефоне интерфейс сворачивается в кнопку «☰».

## Авторизация (auth-web SSO)

Сайт статический, поэтому вход реализован клиентски:

1. `app.js` запрашивает `https://auth.nayanovaacademy.ru/api/check.php`
   (`fetch(..., { credentials:'include' })`) — домен-широкая кука `auth_session`
   на `.nayanovaacademy.ru` распознаётся на портале.
2. Кнопка «Войти» ведёт на
   `https://auth.nayanovaacademy.ru/index.php?page=login&redirect=<текущий URL>`,
   «Выйти» — на `/api/logout.php?redirect=<текущий URL>`.
3. Анонимный вход разрешён: без сессии симулятор работает как обычно, в UI
   показывается «Гость» и кнопка входа. Недоступность auth-web не блокирует игру.

Связанные настройки в других проектах экосистемы (не удалять):

- `auth-web/config.php` → `ALLOWED_ORIGINS` содержит `https://fly.nayanovaacademy.ru`
  (иначе браузерный CORS-ответ `check.php` не читается).
- CSP сайта (`fly.nayanovaacademy.ru`) → `connect-src 'self' https://auth.nayanovaacademy.ru`.

## Технические заметки

- Строгая CSP сервера: **никаких inline-скриптов, importmap и внешних CDN**;
  three.js импортируется относительным путём `./three.module.min.js`.
  Единственное внешнее подключение — `connect-src` к `auth.nayanovaacademy.ru`.
- Файлы отдаются с `Cache-Control: no-cache` (имена без content-hash) — не
  переносить под immutable-кэш.
- Правки — только в `public/`; это готовая статика, отдельного билда нет.
